# デプロイ手順

## Phase 1（静的サイトとして）

外部 DB/API なしで動作するため、そのままデプロイ可能。

### Vercel
1. リポジトリを Vercel にインポート（Framework: Next.js 自動検出）。
2. 環境変数 `NEXT_PUBLIC_SITE_URL` に本番 URL を設定（canonical/hreflang/sitemap の基点）。
3. Deploy。`npm run build` が実行され静的生成（トップ/銘柄24/学習/ランキング/決算/about + sitemap.xml + robots.txt）。

### ローカル本番確認
```bash
npm run build
npm run start   # http://localhost:3240
```

## Phase 5 以降（認証・保存系を本番公開する場合）

⚠️ **重要**: 認証・ウォッチリスト・ポートフォリオ・コミュニティは Supabase（PostgreSQL）を利用します。サーバーレス（Vercel）にインメモリのままデプロイするとインスタンス間でセッション/データが揮発します。**本番公開時は `DATABASE_URL`（Supabase）を必須**とします。

### Supabase 設定
1. Supabase プロジェクト作成 → `DATABASE_URL` / `DIRECT_URL` / `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` を取得。
2. マイグレーション適用（Prisma or Supabase migrations）。
3. **Row Level Security** を全ユーザーデータテーブルで有効化（本人のみアクセス）。
4. マスタ（業種/市場区分/テーマ）を seed 同期。

### 外部データプロバイダー接続
`MARKET_DATA_PROVIDER` 等を `mock` 以外に設定し、`src/lib/providers/index.ts` に live 実装を追加。JPX 上場会社情報・EDINET・TDnet・適法な株価 API を、利用規約・ライセンス・API 制限を尊重して接続（スクレイピング前提にしない）。取得失敗時は mock フォールバック。

## Docker（オプション）

`output: "standalone"` を `next.config.mjs` に追加し、`node:20-alpine` の 3 ステージ（deps→builder→runner）でイメージ化。`docker-compose.yml` に app + postgres16（healthcheck）を定義。

## 環境変数チェックリスト

- [ ] `NEXT_PUBLIC_SITE_URL`（本番 URL）
- [ ] `MARKET_DATA_PROVIDER` ほか各プロバイダー（実データ接続時）
- [ ] `DATABASE_URL` / `SUPABASE_*`（Phase 5 以降）
- [ ] `RESEND_API_KEY` / `EMAIL_FROM`（メール認証）
- [ ] `CRON_SECRET` / `WEBHOOK_SECRET`（バッチ/Webhook）
- [ ] `AFFILIATE_REDIRECT_SECRET`（/go 署名）
- [ ] 秘密鍵が `NEXT_PUBLIC_*` に混入していないこと

## 運用

- **バックアップ**: Supabase 自動バックアップ + 定期エクスポート。
- **マスタ更新**: `src/data/*.json` を更新 → seed 再同期。訂正は `revision_number`/`effective_at` で履歴保持。
- **データ取込**: `/api/cron/import`（`CRON_SECRET` 認証）で定期取得。`data_import_jobs`/`data_import_errors` に記録。失敗時に古い値を最新として見せない。
